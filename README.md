# Board Lab — исследовательский прототип общей доски

Работающий локальный spike для оценки **Excalidraw + Yjs + Hocuspocus**, а не production-аналог Miro.
Проверяем редактор, собственный binding к совместной модели, присутствие, offline/reconnect,
конфликты, личный undo и долговечное хранение. Проект расположен непосредственно в текущей
директории `C:\dev\project-group-08\board`. `PROMPT.md` не изменялся.

**Доступ без авторизации:** имя — только подпись участника. Любой, кто может обратиться к
серверу, может читать, изменять и удалять данные. Это также написано в интерфейсе.

## Быстрый запуск

Требования: **Node.js 24+**, pnpm 9.6+; современный desktop-браузер. Используется встроенный
`node:sqlite`, поэтому отдельный SQLite-сервер, C++ toolchain и API-ключи не нужны.
Проверенное окружение: Windows, Node 24.17.0, pnpm 9.6.0.

```sh
pnpm install --frozen-lockfile
pnpm dev
```

Открыть **http://127.0.0.1:5173/**. Ввести короткое имя и нажать «Открыть общий холст».
Открыть **тот же адрес** в другом браузере / приватном окне, ввести другое имя.
Все клиенты работают с единственным документом `team-board`; имя и URL не являются механизмом доступа.
Обычные вкладки тоже работают, но для демонстрации независимых сессий удобнее приватное окно.

| Назначение | Адрес |
| --- | --- |
| Vite dev UI | `http://127.0.0.1:5173/` |
| UI собранного приложения | `http://127.0.0.1:4173/` |
| Hocuspocus + API изображений | `http://127.0.0.1:1234` |
| WebSocket через Vite | `ws://127.0.0.1:5173/sync` (или `4173`) |
| Health | `http://127.0.0.1:1234/api/health` |

Оба сервера явно слушают **только `127.0.0.1`**. Firewall, системные сервисы и внешняя публикация
не настраиваются. Для остановки — Ctrl+C в терминале запуска.

### Запуск по отдельности и перезапуск sync

Чтобы перезапускать только сервер, используйте два терминала:

```sh
# Терминал 1
pnpm server

# Терминал 2
pnpm web
```

Создайте объект. Дождитесь «Подключено» без «Передаём изменения…».
Остановите `pnpm server`, проверьте статус потери связи, снова выполните `pnpm server`.
Вкладки подключатся автоматически. Откройте ещё одну независимую сессию: объект должен быть там.
Повторите с изображением, загруженным через «+ Изображение».

В **dev-режиме** (`pnpm dev` / `pnpm web`) доступна кнопка «Отключить синхронизацию».
Она вызывает `disconnect()` используемого WebSocket-провайдера только текущей вкладки,
без остановки сервера. Переместите объект, а во втором окне создайте другой.
Нажмите «Подключить синхронизацию» (`connect()` того же провайдера): изменения объединяются.
Индикатор отражает события и реальное состояние провайдера, включая закрытие сокета;
повторное переключение на время закрытия заблокировано. В production-сборке кнопки и dev-подсказки нет.
Это контролируемая проверка отключения одного клиента, **не полноценное моделирование всех сетевых сбоев**.
**Не перезагружайте отключённую вкладку, если нужны её изменения: offline Y.Doc живёт только в памяти.**

Адрес собранной версии — **http://127.0.0.1:4173/**. Preview также проксирует WebSocket и API.

## Что доступно

- Нативные фигуры, текст, стрелки, выделение, перемещение, изменение размеров и удаление Excalidraw.
- Панорамирование (Space + drag / инструмент «Рука»), масштабирование, кнопка «Вся доска».
- Нативная группировка Ctrl+G, разгруппировка Ctrl+Shift+G.
- Список участников, подписи курсоров и выделения через Yjs Awareness / `collaborators` API.
- Создание, изменение и удаление распространяются через Yjs, без ручного обновления страницы.
- PNG / JPEG / WebP до **2 МиБ** через отдельную кнопку; клиентский предел 24 мегапикселя.
- Кнопки «Отменить моё» / «Повторить»: экспериментальный личный Yjs undo/redo.
  Ctrl+Z / Ctrl+Shift+Z вне редактируемого текстового поля направлены в Y.UndoManager.
- Копирование постоянной ссылки, статус связи, пояснения в панели «О прототипе».

Стикер можно составить из прямоугольника и текста: **отдельной модели стикеров нет**.
Вставка и drag-and-drop изображений намеренно блокируются: используйте «+ Изображение»,
чтобы файл сначала оказался в долговечном хранилище. SVG и GIF не поддерживаются этой интеграцией.
Импорт полной сцены и встроенный общий undo не используются.

## Как устроена синхронизация

```text
Excalidraw onChange → изменившиеся объекты → Y.Map elements[id]
                         удаления → Y.Map deleted[id]
                          ↕ Hocuspocus WebSocket
                серверный Y.Doc → бинарный update → SQLite

PNG/JPEG/WebP → HTTP upload → SQLite assets BLOB
                      Yjs хранит только fileId и геометрию
```

- Каждый элемент — отдельный атомарный JSON-регистр в `Y.Map`, **не снимок всей доски**.
  Несвязанные объекты сливаются независимо. При конкурентной правке одного объекта Yjs выбирает
  одну целую запись; геометрия не собирается по полям из разных преобразований.
- Это **не посимвольный CRDT для текста**: одновременное редактирование текста может потерять одну версию.
- Удаление хранится отдельно. Обычная конкурентная/устаревшая правка не снимает tombstone.
  Явный undo автора удаления может снять его; это отдельная проверенная операция.
- Порядок строится по Excalidraw fractional `index`, при равенстве — по id.
- Локальное изменение вычисляется относительно снимка последней показанной сцены.
  Удалённое применение обновляет этот снимок **до** `updateScene`, использует
  `CaptureUpdateAction.NEVER`, очищает внутреннюю историю Excalidraw.
  Пустые Yjs-транзакции не перерисовывают сцену: это важно для непрерывного drag.
- Y.UndoManager отслеживает только `LOCAL_ORIGIN`, а не изменения provider.
  Capture window — 400 мс, на pointer-up разделяются жесты. Семантика сложных действий пока исследовательская.
- Zoom, viewport, локальная библиотека и выделение не сохраняются как общее содержимое.
  Выделение и курсоры передаются как временное присутствие, а не как долговечные данные.

Подробнее о наблюдаемых конфликтах и границах undo: **[RESEARCH.md](RESEARCH.md)**.

## Данные и безопасный сброс

- Основной файл: **`data/board.sqlite`**.
- Таблица `documents`: `Y.encodeStateAsUpdate(document)` как BLOB.
  Загрузка — исходный бинарный Yjs update, без восстановления истории из JSON.
- Таблица `assets`: исходные байты изображений как отдельные BLOB, MIME и SHA-256 id.
  Изображения не передаются base64 в общей CRDT-структуре.
- SQLite: WAL, `synchronous=FULL`. Возможны файлы `board.sqlite-wal`, `board.sqlite-shm`.
  Каждый серверный update синхронно записывает бинарный снимок. Это осознанный компромисс spike:
  простая durability, но дорогая запись всей истории при каждом движении.
- Картинка сначала сохраняется HTTP-запросом, затем добавляется объект-ссылка. Удаление картинки с
  холста не чистит BLOB: garbage collection в spike нет.
- Тестовые БД создаются отдельно в `.test-data/` и удаляются тестами.

Для сброса **закройте все клиенты**, остановите web и sync, затем:

```sh
pnpm reset --confirm
pnpm dev
```

Удаляются только `data/board.sqlite` и его WAL/SHM; исчезнут доска и картинки.
Старая открытая вкладка может повторно загрузить старый Y.Doc на пустой сервер, поэтому закрыть
клиенты перед сбросом обязательно. Без `--confirm` скрипт ничего не удаляет.
`BOARD_DATA_DIR` и `SYNC_PORT` доступны для серверных экспериментов; Vite-прокси настроен на 1234.
Reset поддерживает только стандартную папку `data`.

## Проверки

```sh
pnpm typecheck
pnpm build
pnpm test
pnpm exec playwright install chromium
pnpm test:browser
```

Для `test:browser` нужны свободные **1235** (тестовый sync) и **5174** (тестовый Vite).
Оба поднимаются автоматически; обычную демонстрацию на 1234/5173/4173 останавливать не нужно.
Тестовый сервер использует отдельную SQLite, не `data/board.sqlite`. Раздельные порты также
не дают открытой демонстрационной вкладке переподключиться к тестовой доске.
Интеграционные тесты используют случайные локальные порты, включая проверку принудительного завершения
отдельного серверного процесса. Браузерные тесты сравнивают **сцену редактора**, а не только Y.Doc.
Часть конфликтных действий воспроизводится через dev-only API редактора, чтобы точно задать конкурентные изменения.

Для smoke-проверки уже запущенной собранной версии (sync + preview):

```sh
pnpm test:smoke
```

## Что получилось, что осталось гипотезой

**Подтверждено:** пять критериев завершения из ТЗ выполнены — два независимых клиента,
видимые CRUD/move, reconnect, persistence, сборка и реальные тесты. Все четыре обязательных
конфликтных сценария покрыты интеграционными проверками с перезапуском.

**Не подтверждено / ограничения:**
- Универсально корректное разрешение произвольных пользовательских конфликтов.
  Атомарный регистр обеспечивает схождение, но может потерять намерение одного автора.
- Полноценный продуктовый «отменять только свои действия» для всех операций.
  Проверены конкретные selective undo/redo; сложные binding/group/frame/text-операции,
  разбиение длинного drag и текстового ввода на undo-единицы требуют отдельного проектирования.
- Offline-сохранение между reload отсутствует; нет IndexedDB-копии и service worker.
  Холодное открытие при недоступном сервере не даёт редактировать неполученную доску.
- Исчезновение присутствия при чистом disconnect проверено. Тайминги при «чёрной дыре» сети,
  sleep/hibernate и длительном отсутствии пакетов отдельно не измерены.
- Firefox, Safari, настоящие мобильные устройства, touch/stylus, доступность screen reader,
  высокая нагрузка и тысячи объектов не проверялись. На ширине 390 px проверено отсутствие
  горизонтального overflow документа, но часть desktop-инструментов редактора обрезается:
  мобильная эргономика не является закрытым результатом spike.
- Нет схемной валидации произвольных Yjs-записей и защиты от клиента, обходящего UI.
  Проверка сигнатуры файлов и размера не заменяет безопасный image-processing pipeline.
- Нет серверных прав, аккаунтов, ролей, лимитов на общий размер доски/хранилища,
  резервных копий, GC BLOB/tombstone, версий данных и масштабирования.
- Индикатор связи не является отдельной транзакционной квитанцией `fsync` клиенту.
  Проверен restart после доставленных обновлений; сбои диска и питание посреди записи не моделировались.
- Размер bundle Excalidraw существенен; оптимизация загрузки не выполнялась.

## Как проверить самостоятельно

1. Откройте один URL в обычном и приватном окне, задайте «Аня» / «Борис».
   Покажите список участников и курсоры. Обратите внимание на подпись «без авторизации».
2. Нарисуйте прямоугольник, добавьте текст и стрелку. Переместите объект,
   удалите его, отмените своё удаление. Выделите несколько объектов и сгруппируйте Ctrl+G.
3. В dev-версии у Ани нажмите «Отключить синхронизацию». Переместите объект. У Бориса создайте другой.
   Подключите Аню: оба изменения видны. Покажите предупреждение о потере offline-данных при reload.
4. Загрузите маленький PNG. Остановите и поднимите только `pnpm server`.
   Откройте третью сессию: фигуры и изображение восстановлены из SQLite.
5. Переместите один объект у Ани, затем у Бориса. У Ани нажмите «Отменить моё»:
   поздняя правка Бориса сохраняется. Покажите таблицу конфликтов в `RESEARCH.md` и сформулируйте
   вывод: стек подходит для следующего PoC, но семантика undo и сложных конфликтов ещё требует работы.
